# Development 0.8.0 — P02 saved-world descriptor reconciliation

The [fixed P02 checkpoint](../planning/prompt-roadmap.md) establishes deterministic world inputs, immutable per-game baselines and compatibility diagnostics. Its policy explicitly separates these diagnostics from a pre-physics game-load blocker. The baseline cannot silently adopt a changed/future/malformed world merely because it was loaded or saved.

## Implementation

Core descriptors and catalogs canonicalize and fingerprint stable/native identity plus supported world inputs. Reconciliation reports exact match, safe additions, missing/changed inputs and unverified or unusable states. Map fingerprints are captured from the bytes actually decoded. The per-game native scenario preserves saved records and semantic extensions, requires explicit first adoption, exposes a diagnostic panel and restores descriptors through native save/reload. See the [policy and schema guide](../modders/saved-world-baselines.md).

The existing five celestial fixtures retain their geometry, configuration and assets. There is no new playable torus, vessel anchor, migration engine or enforced unsafe-game load prevention.

## Reflection

The checkpoint's main result is an explicit compatibility boundary and an immutable per-game baseline. Independent review identified a property-cap regression for valid 256-biome bodies and a future-scenario envelope that could have been offered first adoption; both were repaired before final validation. Strict tokens, provider identifiers and catalog integrity also prevent normalization/omission from silently changing record meaning.

The benchmark is deliberately narrower than unsafe-game prevention: ordinary native scenario callbacks cannot certify pre-physics admission. Actual changed/future game-scenario loads and player GUI rendering/input remain untested; mutation fixtures operate on native ConfigNode copies and the explicit API. Wire-format checks use a known SHA vector plus order/culture cases, without a retained frozen descriptor/catalog expected vector. No stock/third-party geometry archive or live runtime mutation monitor is installed. These limits must be reflected in the independent grade rather than hidden by the passing assertion count.

The [independent review](p02-review.md) scored P02 **96/100**, with criteria 1–5 met and no unresolved major defect. The four-point deduction reflects those integration/GUI/wire-fixture gaps. My assessment is that P02 achieved its predefined diagnostic/preservation goal and exposed the remaining admission boundary honestly. The next `continue development` starts P03; `redo development` retries P02.
