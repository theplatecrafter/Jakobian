# Development 0.9.0 — P03 detached torus construction and scaled preview

The [P03 checkpoint](../planning/prompt-roadmap.md) fixes a deliberately detached construction boundary. Inspecting native lifecycle behavior showed that global torus registration would expose an unsupported destination before P04 admission exists. The proposed publication scope was revised before coding: P03 publishes an inactive native prefab in an owner-scoped preview registry, not in the live celestial system. Real Map/Tracking/Flight integration remains pending.

## Implementation

An immutable torus definition validates stable/native identity, geometry, reference/dynamics metadata and preview-only capability, and supplies coherent geometry/charts/P02 descriptors. A bounded shared-index whole mesh provides watertight periodic topology and analytic normals. Tessellation is independent of saved world identity.

The native registry binds inactive PSystemBody/CelestialBody/orbit metadata and a separately owned 1:6,000 renderer. It owns an isolated scene, camera, mesh/material/texture/target resources and rejects duplicate/colliding identities. No live-system lists, parent child lists or active world catalog are changed. A guarded human MainMenu launcher offers view controls; the automatic fixture checks construction, GPU silhouette, isolated picking, persistence and cleanup. See [API/human guide](../modders/detached-torus-preview.md).

## Reflection

Review and human testing improved this increment materially. The first UI used tiny/transparent default styling; larger styles and an opaque panel made it readable. A transparent UGUI blocker did not intercept KSP's TextProButton3D menu, so it was replaced with an owned native MAIN_MENU lock and re-tested. Review also prompted explicit asset-destruction checks, input/collision fixtures, launcher guarding and disabling the renderer outside its own capture to prevent native-camera contamination. Preliminary captures/runs are distinct from the final tested binary set.

This achieves the frozen detached-construction boundary, not the initially forecast live-system/map integration. Native GPU/PhysX checks certify the shipped R=9,000 m/r=1,500 m, 128×64 profile; extremes near thin-tube/closed-hole or coordinate limits remain core/source-covered rather than fully native-certified. Foreign render-layer occupancy and overlapping foreign MAIN_MENU locks are code-inspected; the native lock fixture directly preserves a foreign QUICKSAVE lock. Input/renderer failures and broader mod profiles need more coverage. No playable torus, contact physics, saved vessel anchors, centrifuge or arbitrary geometry program is added.

The [independent assessment](p03-review.md) scored P03 **97/100**, with all five criteria met and no unresolved major defect. Three points were deducted for native parameter breadth and failure/interoperability coverage. My assessment is that the narrowed construction goal was accomplished, and desktop testing prevented shipping an unreadable/click-through preview. The grade does not measure overall framework completion. `continue development` advances to P04; `redo development` retries P03.
