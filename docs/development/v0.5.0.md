# Development 0.5.0 — mapped radial terrain and native biomes

This slice adds a useful authoring backend without making radial assumptions part of the general-body API. The accepted [mathematical bodies and fields](../architecture/mathematical-bodies-and-fields.md) design remains the scope for function-defined solids, rotating habitats, distributed mass and influence volumes.

Implemented:

- Immutable periodic PNG8 maps with explicit pole, interpolation, nearest-palette and path rules.
- A displaced radial surface shared by native PQS, scaled meshes, ground/normal queries, camera clearance and flight probe setup.
- A Windows shader bundle built with Unity 2019.4.18f1. Albedo uses continuous encoded directions instead of interpolating a longitude seam across a triangle.
- An owned material setup for every PQS quality tier. Native quality selection can no longer select a shared mutable stock material for a new body.
- A native `CBAttributeMapSO` bridge for science and resource biome lookup, stable biome names and compiled stock-chart map data.
- A new Atlas ellipsoid with deterministic original height/color/biome images, crater terrain and four biomes. The existing four bodies' configuration bytes, names, indices, shapes and rotation are retained.
- Asset/source hash checks and deployment records covering all installed test-pack files and the shader bundle, alongside the two DLLs.

See [radial map authoring](../modders/radial-maps.md) for the implemented schema and restrictions. Atlas occupies index 21; these changes do not convert old fixture saves into new terrain.

## Validation scope

The zero-warning Release build passes 122,589 core assertions, including interpolation oracles, periodic wrap, exact palette classification, polar agreement, input ownership, displacement limits, ground/datum distinction, bounds and independent normal stencils. An initial native run caught a roundoff seam where a tiny negative longitude became UV=1; the fix explicitly wraps that endpoint and the tests now include the complete scaled-mesh grid.

The final build passed native startup checks for all five fixtures, the isolated torus foundations, 2,520 Atlas height/science-biome samples, finished contact-mesh direction/material checks, and a native GPU render containing all tested palette classes. Atlas passed actual terrain contact, landing, navigation, both altimeter modes, camera clearance and save/reload. All six retained 0.2.0/0.3.0 landed capsules passed upgrade/reload checks, followed by a stock Kerbin orbit coast/reload. Both final probe logs are exception-free through normal MainMenu shutdown. Exact tested hashes, logs, save names, screenshots and scope are in [v0.5.0-validation.json](v0.5.0-validation.json).

The final Atlas and regression runs used identical DLL/asset/config bytes. The earlier four-body fresh flight also passed contact/navigation/reload, but exposed a visual channel issue; it is retained as superseded evidence rather than being called final texture acceptance. Only the seven private copies created by the current regression were archived under baseline's `.dev/regression-results`; original/staged inputs and the template managed assemblies remained byte-identical. The baseline instance is deployed with the tested files and no probe is left running.

Visual QA caught a separate integration error after the initial flight checks passed: the stock planet-relative PQS modifier rewrites UV/UV2 after vertex callbacks, corrupting the shader's direction input. The mapped shader now uses UV3/UV4 while leaving native channels intact. Contact-mesh checks validate the finished tile channels and actual material/texture; an isolated GPU render checks multiple albedo palette regions. A first diagnostic also accidentally selected a retained template prop rather than a PQS tile; its selector now requires the actual `PQ` component. Failed-run logs are retained as development evidence, not successful validation.

## Remaining limits

Atmosphere and water are not enabled. They need spatial occupancy, moving-medium physics, per-part integration, scene/warp persistence and consumer adapters. Color maps alone do not provide resource deposits, water or physical ice. Native abundance remains owned by KSP ResourceMap; scanners, drills, science modules, career/archive UI and custom resource distributions require further tests.

This remains single-valued radial displacement with bounded PNG8 data and no streaming, caves, function programs or general-body runtime. Torus solid/mesh foundations are retained, but a torus celestial fixture and centrifuge habitat still require the nonradial lifecycle/contact/anchor path. A native spherical SOI and central point mass remain authoritative in this build; arbitrary influence domains and numerical flight are design/implementation milestones.

Rendering is a first custom macro-albedo material backend (256x129 fixture maps, with no fine detail/normal/splat texturing), with no certified EVE/Scatterer/Parallax integration, resource overlay, mipmap/on-demand pipeline or non-Windows graphics coverage. Visual transitions, shadows, ordinary camera movement and terrain tessellation need human acceptance beyond the automated fixture.
