# Development 0.3.0 — shared surface context and navigation

The current shape family now has a shared geometry/navigation context, a labeled ground/datum flight readout and an external-camera endpoint guard. The architecture and API semantics are in [surface context](../architecture/surface-context.md).

Implemented:

- Analytic normals and signed radial/down-ray clearance for sphere, ellipsoid, superellipsoid and peanut; explicit heading ambiguity at poles.
- A live-body query bridge with stable IDs, correct native/Unity coordinate conversion, physical gravity, corotation velocity, vacuum/dry capabilities and snapshot time/frame.
- A native planetary resource-request coordinate bridge; abundance and scanning/biome rules stay with stock ResourceMap.
- An F8 surface readout and an optional 2 m camera endpoint constraint, scoped to external Flight mode and owned radial bodies. Camera presentation offsets are restored before the next native camera update rather than fed back into zoom/heading smoothing.
- Native query, navball, altimeter/cache, vacuum, resource-coordinate and camera guard probes, alongside existing contact/landing/reload tests.

Gravity up remains the physical point-gravity vertical. Surface normal is independently reported as terrain slope. No custom-force, global vessel-cache, resource-harvesting or intake patch has been installed. General topology, rotating-habitat apparent vertical, spatial air/water and resource/biome map authoring remain future work.

The body fixture configuration is byte-identical to 0.2.0: identities, dimensions, rotation and orbits are unchanged. Builds continue to deploy into baseline without replacing player saves. Pure-core tests pass **86,039 assertions** and Release builds have zero warnings/errors.

## Native verification

The final deployed build passed the normal-graphics suite on the ellipsoid, cube and peanut:

- Four startup geometry/frame/context checks, including the spherical control and stock-body query exclusion.
- Six navigation/cache/vacuum/resource checks: approach and landed reload for each nonspherical body. Actual native navball orientation, vessel/global up, datum/radar altitude and surface velocity agree with the context within declared tolerances.
- Twelve actual altimeter-mode checks: ASL and AGL before landing and after reload, restoring the original UI mode afterward.
- Three deliberate underground camera corrections, with unchanged native pitch/heading/zoom, stock-body exclusion and ten subsequent native camera updates per body.
- Three real terrain collider/landing passes and three landed save/reload passes, using test-only braking as an engine substitute.

Exact binary/config hashes, per-body measurements, native Ore results, saves, test tolerances and investigation history are in [v0.3.0-validation.json](v0.3.0-validation.json). The final log has no exception tokens before the suite pass marker. The native KnowledgeBase/MapView null reference still occurs during shutdown afterward and remains unresolved.

The first camera test fixture rotated the camera parent after placing its endpoint, so it did not actually start underground. The corrected fixture verifies its negative starting clearance before calling the production guard. A separate scope fixture tried to inspect a native prefab after native destruction at MainMenu; that lifetime-invalid test was removed. Production queries use live-body object identity, and stock-body exclusion remains tested. Screenshot review also aligned the readout to the same centre-of-mass point as native altitude caches.

## Remaining acceptance work

Camera swept-line/near-plane behavior, interactive IVA/map/scene transitions, long-duration contact, EVA/wheels/fleets/warp and third-party profiles are not certified. Terrain material/color seams remain visible. Resource extraction/scanning, custom maps/biomes and arbitrary air/fluid/field providers remain separate work. This suite reloads saves it creates; it does not constitute a full 0.2.0-to-0.3.0 upgrade test. Older task-created saves are retained under baseline's `.dev/older-probe-saves` without deletion.
